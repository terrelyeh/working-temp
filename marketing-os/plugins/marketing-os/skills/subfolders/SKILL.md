# 建立子資料夾技能

負責在既有行銷工作區內，臨時建立新資料夾，並確保它符合部門標準結構。
（大量標準夾一次建好請用 `/marketing-os:begin-marketing`；本技能處理之後的單一、隨需建立。）

## 開始之前
先設定預期，再**逐題**訪談（像對話，不要一次全丟）：

> 「我幫你開這個資料夾，先問幾個小問題，想跳過隨時說一聲。」

## 訪談（缺才問，使用者已說的就跳過）

### 1. 用途
> 「這個資料夾要做什麼用？」（開放式）

### 2. 名稱
若沒給，用 **AskUserQuestion** 依用途建議 2～3 個名字。

### 3. 位置
先看現有結構，用 **AskUserQuestion** 問要放哪，用大白話（不要講「路徑/目錄」）：
- 📁 放在主工作區頂層
- 📂 放進某個標準夾底下（例如活動企劃/、廣告投放/）——若用途相關就主動建議
若工作區只有根目錄，直接放根、跳過此問。

### 4. 身分覆寫（選用）
用 **AskUserQuestion**：
> 「我在這個資料夾工作時，要用不一樣的角色嗎？」
- 👤 跟平常一樣
- 🎭 [依用途給具體角色，例如活動夾→活動企劃、投放夾→投放分析師、內容夾→資深編輯]
- 🆕 自訂
選「跟平常一樣」時，CLAUDE.md 就不加身分段落。

### 5. 記憶隔離（選用）
讀上層資料夾的 CLAUDE.md / MEMORY.md，若有**該工作區專屬**、且對新夾有用的條目，用 **AskUserQuestion**（多選）讓使用者勾要不要帶過來；一律含「什麼都不帶，從頭開始」。
- **不要帶任何來自個人偏好的內容**（名字、風格、工具那些每次都在）。
- 上層沒有有意義的內容就跳過這步，不要硬湊。

## 建立檔案

### 新資料夾內的 CLAUDE.md，包含：
1. **資料夾用途**
2. **身分覆寫**（僅在使用者要求時；註明此處覆蓋個人偏好）
3. **建議技能**：依用途提示常用哪個技能（活動→campaign-brief、內容→social-post、投放→ad-copy、競品→competitor-scan、回顧→weekly-report）
4. **記憶系統**（逐字包含）：
   > 本資料夾含一個 MEMORY.md，是跨會話的外部記憶。
   > - 每次會話開始先讀 MEMORY.md，用它指導工作，不用刻意宣告。
   > - 記憶只由使用者觸發：只有使用者說「記一下 / 記住這個 / 別忘了」時才寫入。
   > - 記憶持久：除非使用者要求刪除或修改，否則保留。
   > - 衝突要提示，不要悄悄覆蓋。

### 新資料夾內的 MEMORY.md：
```
# Memory

_最後更新：[今天的日期]_

## Memory
<!-- 使用者要求記住的事。持久保留，除非使用者要求刪除或修改。 -->
```
若第 5 步有勾要帶過來的條目，加到 `## Memory` 底下。

## 收尾
3～4 句總結：建了哪個夾、放在哪、CLAUDE.md 有什麼、MEMORY.md 是否已有初始條目。不要過度解釋。

## 邊界情況
- **使用者要跳過訪談**：用現有資訊給合理預設，建好夾配一份含用途與記憶系統的基本 CLAUDE.md，之後可再補。
- **巢狀資料夾**：夾裡再建夾，同流程，先問清楚放哪。
- **重新命名**：那是另一個請求，本技能只負責建立。
